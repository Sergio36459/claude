# Этап 2. Предлагаемые улучшения проекта

Улучшения сгруппированы по эффекту. Помеченные **[в MVP]** включены в план разработки сразу — они дешевле на старте, чем при доработке. Остальные — в бэклог после запуска.

## 1. Скорость и стоимость: «статика прежде всего»

**Улучшение №1 (ключевое): пре-генерация дневных бандлов.** Исторические данные неизменяемы. Вместо того чтобы каждый запрос считался в API, ETL после публикации дня генерирует статические файлы:

```
/data/days/2023-06-06/bundle.json      — события + статистика + потери дня
/data/days/2023-06-06/control.z{0-3}.geojson — зоны контроля, 4 уровня упрощения
/data/days/2023-06-06/frontline.geojson
/data/days/2023-06-06/diff.geojson     — что изменилось со вчера
/data/series/control-area.json         — временные ряды для графиков (один файл на серию)
```

Файлы кладутся в объектное хранилище за CDN с `Cache-Control: public, max-age=31536000, immutable`. **Эффект:** 95%+ трафика не касается API и БД; воспроизведение 60x реально, потому что клиент просто качает и кэширует маленькие статические файлы; стоимость хостинга падает на порядок. API остаётся для поиска, сложных фильтров и админки. **[в MVP]**

**Улучшение №2: PMTiles вместо тайл-сервера.** Векторные тайлы подложки и детальной геометрии — в формате [PMTiles](https://protomaps.com/docs/pmtiles): один файл в объектном хранилище, читается HTTP range-запросами, тайл-сервер не нужен вовсе. MapLibre поддерживает через официальный протокол-плагин. **[в MVP]**

**Улучшение №3: режим воспроизведения с адаптивной детализацией.** При скоростях ≥5x карта автоматически переключается на самый грубый уровень упрощения (z0) и отключает per-feature-анимации, при паузе — догружает детальный уровень. Это гарантирует 60 FPS даже на 60x. **[в MVP]**

## 2. Достоверность и доверие

**Улучшение №4: паспорт данных у каждого факта.** Не просто ссылка на источник, а всплывающий «паспорт»: источник, дата публикации источника, дата загрузки в систему, уровень достоверности, есть ли расхождения с другими источниками. Это то, что отличает аналитическую платформу от агрегатора. **[в MVP — модель данных; UI-паспорт можно упростить]**

**Улучшение №5: страница методологии.** Отдельная страница: откуда данные, как сверяются, что значит каждый уровень достоверности, известные ограничения каждого источника (например, «Oryx — только визуально подтверждённые потери, реальные выше»). **[в MVP]**

**Улучшение №6: видимые расхождения.** Там, где источники противоречат, UI не прячет конфликт, а показывает бейдж «источники расходятся» с раскрытием всех версий.

## 3. UX-возможности, которых нет у конкурентов

**Улучшение №7: URL как состояние.** Дата, вьюпорт (центр/зум), активные слои и фильтры кодируются в URL (`/map/2023-06-06?lat=..&lng=..&z=..&layers=..`). Любую сцену можно отправить ссылкой; OG-image генерируется на дату. **[в MVP]**

**Улучшение №8: режим сравнения двух дат.** Свайп-шторка (как в спутниковых сравнениях) или режим «призрак»: полупрозрачная линия фронта даты A поверх даты B. Мгновенно отвечает на вопрос «что изменилось за N месяцев».

**Улучшение №9: диф-панель «Что изменилось за день».** Автоматический текстовый+числовой дайджест: км² изменения контроля по направлениям, количество событий по типам, крупнейшее событие дня. **[в MVP — упрощённая версия из precomputed diff]**

**Улучшение №10: маркеры ключевых дат на таймлайне.** Освобождение Херсона, падение Бахмута и т.п. — насечки на шкале с подписями, работают как быстрая навигация.

**Улучшение №11: «туры» (guided stories).** Скриптованные проигрывания: «Битва за Киев», «Харьковское контрнаступление» — камера + даты + аннотации. Отличный источник органического трафика.

## 4. Архитектура и данные

**Улучшение №12: ETL как отдельное приложение с контрактом.** Пайплайн загрузки (ISW/ACLED/Oryx/DeepState) — отдельный воркспейс-пакет с валидацией через zod/JSON Schema, идемпотентными загрузками и журналом импортов. Публикация дня — атомарная транзакция + генерация статики. **[в MVP]**

**Улучшение №13: хранение геометрии «снапшот + дельта».** Полные снапшоты зон контроля раз в неделю (keyframe), между ними — дельты (`ST_Difference`). БД компактна, восстановление любого дня — O(7) операций, а для фронтенда всё равно отдаются пре-генерированные файлы. Подробно — этап 6.

**Улучшение №14: публичный экспорт данных.** `GET /api/v1/export?date=...&format=csv|geojson` + дамп на CDN. Журналисты и исследователи станут амбассадорами проекта.

**Улучшение №15: i18n с первого дня.** Каркас next-intl (UA/EN как минимум) закладывается сразу — ретрофит локализации всегда дороже. Контент событий хранится с языковыми полями. **[в MVP — каркас, один язык контента]**

## 5. Устойчивость

**Улучшение №16: деградация анимаций.** Определение слабого устройства (кол-во ядер, `prefers-reduced-motion`, FPS-проба) → отключение морфинга, замена на кросс-фейд. **[в MVP]**

**Улучшение №17: офлайн-устойчивость данных.** Все сырые ответы источников архивируются (raw layer) до нормализации — если источник изменит формат или исчезнет, история воспроизводима.

---

## Самопроверка этапа 2

- Риск переусложнения MVP: из 17 улучшений в MVP включены только те, что дешевле делать сразу (статика, PMTiles, URL-состояние, ETL-контракт, i18n-каркас, деградация) — остальные не блокируют запуск.
- Улучшение №13 (дельты) добавляет сложность ETL; компенсация — снапшоты-keyframe'ы еженедельно, что упрощает отладку и ограничивает глубину реконструкции.
- Пре-генерация (№1) создаёт риск рассинхрона статики и БД → правило: единственный писатель статики — шаг «publish» ETL, файлы версионируются манифестом (`/data/manifest.json` со списком доступных дат и версией схемы).
