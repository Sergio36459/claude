# Этап 1. Анализ требований

Проект: **интерактивная веб-платформа с хронологией войны в Украине** (рабочее название — *Ukraine War Timeline*, далее UWT).

## 1. Суть продукта

Пользователь открывает сайт и сразу видит интерактивную карту Украины с временной шкалой внизу. Выбор любой даты начиная с **24.02.2022** синхронно меняет **всё** состояние приложения: линию фронта, зоны контроля, события, статистику, графики, потери. Переходы между датами анимированы — пользователь визуально видит эволюцию фронта день за днём, включая режим автовоспроизведения.

## 2. Функциональные требования (сводка и декомпозиция)

### 2.1. Карта (FR-MAP)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-MAP-01 | Рендеринг через MapLibre GL JS (WebGL, GPU) | Must |
| FR-MAP-02 | Zoom, drag, инерция, плавная камера | Must |
| FR-MAP-03 | Слои: границы Украины, области, города, нас. пункты | Must |
| FR-MAP-04 | Слои: линия фронта, зоны контроля сторон | Must |
| FR-MAP-05 | Слой территориальных изменений за день (занято / освобождено) | Must |
| FR-MAP-06 | Слои событий: боевые действия, ракетные удары, атаки БПЛА | Must |
| FR-MAP-07 | Направления наступлений (стрелки/векторы) | Should |
| FR-MAP-08 | Военные объекты — только при подтверждённых источниках | Should |
| FR-MAP-09 | Плавная интерполяция при смене даты (не мгновенная перерисовка) | Must |
| FR-MAP-10 | Анимационное выделение изменений: потери — красная пульсация, освобождение — отдельная анимация | Must |
| FR-MAP-11 | Настройки карты: включение/выключение слоёв, стиль подложки | Must |

### 2.2. Timeline (FR-TL)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-TL-01 | Навигация: ±день, ±месяц, ±год | Must |
| FR-TL-02 | Ползунок по всему диапазону дат | Must |
| FR-TL-03 | Прямой ввод даты + календарь | Must |
| FR-TL-04 | Автовоспроизведение со скоростями 0.25x–60x | Must |
| FR-TL-05 | Диапазон: 24.02.2022 → последняя загруженная дата | Must |
| FR-TL-06 | Маркеры ключевых событий на шкале | Should |
| FR-TL-07 | Горячие клавиши (← → пробел и т.д.) | Must |

### 2.3. События (FR-EV)

- Категории: изменения фронта, боевые действия, ракетные удары, дроновые атаки, международные, политические, экономические, санкции, заявления.
- Атрибуты события: заголовок, описание, координаты (опционально — не все события геопривязаны), дата, время (может отсутствовать), **уровень достоверности**, **список источников со ссылками** (≥1 обязателен).
- Панель событий слева, синхронизирована с датой и фильтрами; клик по событию — фокус камеры на координатах.

### 2.4. Потери (FR-LOSS)

Ключевой инвариант данных: **оценки разных источников никогда не агрегируются в одно число**. Каждая оценка — отдельная запись с источником; UI показывает их отдельными колонками/сериями.

- Личный состав: Россия / Украина, по источникам (Генштаб ВСУ, МО РФ, BBC/Mediazona, UALosses, западные оценки — каждая колонка отдельно).
- Техника по категориям: танки, БМП, БТР, артиллерия, ПВО, самолёты, вертолёты, БПЛА, корабли (Oryx — визуально подтверждённые; официальные заявления — отдельно).
- Поимённые проекты (BBC/Mediazona, UALosses) помечаются как «подтверждённые случаи, нижняя граница».

### 2.5. Графики (FR-CH)

Площадь контроля, динамика линии фронта, потери техники, интенсивность боевых действий, динамика событий. Все графики синхронизированы с выбранной датой (курсор/маркер даты) и диапазоном.

### 2.6. Поиск (FR-SRCH)

По городу, области, операции, событию, военной части, дате. Единая строка поиска с типизированными результатами; выбор результата перемещает камеру и/или дату.

### 2.7. Источники данных (FR-SRC)

Приоритет: ISW → ACLED → Oryx → DeepState (сверять) → официальные заявления сторон (отдельными колонками) → поимённые проекты. Инварианты:

1. Каждый факт обязан иметь ссылку на источник.
2. Противоречащие данные сохраняются все, с указанием источника.
3. Альтернативные оценки никогда не удаляются.
4. У каждой записи — уровень достоверности (confirmed / reported / claimed / disputed).

## 3. Нефункциональные требования

| Категория | Требование |
|-----------|-----------|
| Производительность | Десятки тысяч событий, тысячи геообъектов без заметных задержек; смена даты < 300 мс до начала анимации; TTI главной < 3 с на 4G |
| Анимация | 60 FPS на карте при воспроизведении на среднем ноутбуке; деградация до кросс-фейда на слабых устройствах |
| Масштабируемость | Данные append-only; исторические дни неизменяемы → агрессивное кэширование и CDN |
| UI/UX | Тёмная/светлая тема, адаптивность (мобильные, планшеты, большие мониторы), горячие клавиши, сохранение настроек |
| Доступность | Клавиатурная навигация, `prefers-reduced-motion`, контрастность WCAG AA |
| Надёжность данных | Полная трассируемость: факт → источник → дата загрузки → версия ETL |
| SEO/шаринг | URL кодирует дату/вьюпорт/фильтры; OG-превью на дату |

## 4. Роли и сценарии

- **Читатель**: смотрит текущее состояние, листает дни, запускает воспроизведение.
- **Исследователь/журналист**: ищет конкретные события, сверяет источники, выгружает данные, делится ссылкой на конкретную дату/место.
- **Редактор данных (внутренняя роль)**: управляет ETL, валидирует конфликты источников, публикует новые дни.

## 5. Ограничения и риски

1. **Лицензии данных.** ISW/ACLED/DeepState/Oryx имеют разные условия использования (ACLED требует регистрацию и атрибуцию; DeepState — неофициальный источник). До продакшена нужен аудит ToS каждого источника и явная атрибуция в UI. Данные храним у себя (собственная нормализованная копия), а не хотлинкуем.
2. **Гео-точность.** Линии фронта разных источников расходятся; фиксируем источник геометрии на каждый день и не смешиваем геометрии разных источников в одном слое.
3. **Морфинг полигонов.** «Честная» интерполяция произвольных мультиполигонов нестабильна; проектное решение — интерполяция линии фронта + кросс-фейд зон + анимированные диф-полигоны (см. этап 6).
4. **Объём данных.** ~1600+ дней × геометрия + десятки тысяч событий: требуются уровни упрощения геометрии и статическая генерация дневных бандлов.
5. **Чувствительность темы.** Только верифицируемые открытые данные, нейтральная подача, никакой оперативной информации, способной навредить (правило: публикуем только то, что уже опубликовано в приоритетных источниках).

## 6. Вне рамок (MVP не включает)

- Пользовательские аккаунты и краудсорсинг данных.
- Комментарии/соцфункции.
- Прогнозные модели.
- Реалтайм-обновления чаще 1 раза в сутки.

## Самопроверка этапа 1

**Слабые места и как они закрыты:**

- *Не задан явный SLA свежести данных* → принято: обновление 1 раз в сутки после выхода сводки ISW; «сегодняшний» день помечается как предварительный.
- *События без координат* (санкции, заявления) → координаты опциональны; такие события живут только в панели и на шкале, не на карте.
- *Расхождение источников по геометрии фронта* → одна «каноническая» геометрия в день (DeepState как оперативная основа, сверенная с ISW), источник фиксируется в метаданных; альтернативные оценки — в атрибутах, не в геометрии.
- *Скорость 60x* = 60 дней/сек — сеть не успеет → решается предзагрузкой упрощённых геометрий диапазона и понижением детализации во время воспроизведения (этапы 3 и 6).

**Предлагаемые улучшения** вынесены в `02-improvements.md`.
